# 连接检查

用于确认一次只读检查能否取得明确设备的身份与状态证据。只可使用 Fieldkit 的缓存、目标列表和诊断工具；不要读取源代码仓库，也不要执行运动、停止、复位、保存、清错或维护。

先遵守用户对读取范围的限定。用户要求“只读取缓存”“不主动请求”时，仅调用无参数的 `fieldkit_snapshot({})`，由工具使用本对话人工已选绑定；不运行 `fieldkit_devices`、`fieldkit_diagnose` 或 `fieldkit_diagnose_usb` 作为前置步骤或替代。缓存工具不存在、模式不支持、没有人工绑定、绑定过期或缓存读取失败时，明确报告能力不可用或缺口并停止；不得为了补齐状态改做主动读取。已返回的缓存原文足以支持哪些判断，就只报告那些判断。

缓存中的 `identity.received_age_ms` 是 Identity 缓存的接收年龄，不能称为遥测样本年龄；`telemetryReceivedAgeMs` 属于服务返回的遥测接收年龄。两者不能互相替代，也不能以较旧的 Identity 年龄推断当前身份已经改变、设备失联或当前遥测过期。缺少年龄或来源信息时保留缺口，不主动补读。

只有用户请求主动只读检查或诊断且没有缓存限定时，才执行以下步骤：

1. 运行 `fieldkit_devices`，读取候选、当前模式和当前对话的选择。候选列表不能代替用户选择。
2. 默认 `service-v2` 或显式 `integration` 兼容模式下，使用工作台已经选定的绑定。服务不可用时，引导用户在工作台核对设置、发现或启动服务；生命周期操作只能由人工按钮执行。没有绑定时请用户在工作台选择目标；不得根据序号、排序或其他对话的记录自动绑定。已有明确选择时不重复询问。
3. 用当前对话返回的精确绑定编号调用 `fieldkit_diagnose({ bindingId })`。仅在显式 `legacy-cli` 模式下，才用用户明确选择的完整 USB 序列号调用 `fieldkit_diagnose_usb({ serial })`。
4. 报告所选目标、UID、`run_nonce`、绑定代次、各步骤结果、保存的证据路径和缺失项。首次失败即使用已保留的部分证据，不自动重试或切换模式。只呈现本对话生成的报告。

把工具返回的原始事实称为“证据”；把对连接可用性或后续排查的解释称为“判断”。只有同一 UID、运行实例和绑定代次的证据才可关联。绑定和六个证据步骤不能证明原子状态、设备采用、机构动作或全局安全。未知设备效果应保留为未决项，读取成功不清除它。服务启动结果未知时引导人工发现和核对，不重复启动、不自动切换模式。token 文件仅由主机进程读取，不请求用户粘贴凭据到界面或对话。取消采集、取消选择、关闭页面和 DSH 卸载插件不发送 Stop、不 kill 服务；显式退出服务也不证明设备停止。
