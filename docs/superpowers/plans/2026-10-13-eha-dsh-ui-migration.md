# EHA 统一 DSH 界面迁移计划

> 状态：待评审方案。本文只定义迁移，不授权实现、设备操作、删除旧界面或发布。后续实施按阶段交付，可使用 subagent-driven-development 或 executing-plans；每个阶段独立验收。

**目标：** DSH 承担唯一产品图形界面，eha-tool 保留独立设备服务和 CLI，eha-sdk 保持协议与公共语义的唯一实现。

**架构：** 官方 DSH 原样加载 Fieldkit 插件。全部 EHA 页面、按钮、配置入口、对话工具与服务连接管理均由插件提供；插件后端调用独立的 eha-tool 服务。设备连接、心跳、控制、试验、记录和结果判断在服务中执行，服务生命周期独立于界面与模型服务。

**技术栈：** 现有 DSH 插件、原生对话与 Remote，Rust eha-tool/eha-sdk，本机认证 HTTP。沿用现有构建工具，不增加自研桌面外壳或设备协议实现。

**设计依据：** 本文的目标、职责和接口约定；当前基线为 dsh-fieldkit `b516ceb`、eha-sdk `c91b806`、eha-firmware `af98ce69`。资料核对日期为 2026-10-13。

## 目标与边界

| 层 | 保留或新增的职责 | 不迁入的职责 |
| --- | --- | --- |
| DSH 宿主 | 原样使用公开的插件加载、布局、原生会话、模型配置和 Remote 能力；源代码改动为零 | EHA 页面、专用宿主 API、设备协议、设备控制循环 |
| dsh-fieldkit | 全部 EHA 产品界面、内部导航、服务设置与启动、连接表单、遥测与曲线、配置编辑、控制与试验表单、记录查看、对话工作流 | 直接打开 USB/CAN、维护第二份 SDK 状态机 |
| eha-tool 服务 | 单一设备连接持有者、连接档案、身份校验、调度、SDK 调用、试验、记录、受限 API | 产品页面、聊天、模型决策 |
| eha-tool CLI | 离线检查、脚本与终端操作、服务管理；复用同一执行逻辑 | 因服务故障而静默另开设备连接 |
| eha-sdk 与固件 | 现有通信合同、数值规则、设备公共行为及实际控制 | 将桌面请求编号包装成设备操作确认 |

“唯一 UI”指只维护 Fieldkit 这一份 EHA 图形界面；在官方 DSH Web 或已通过兼容验收的官方 Desktop 中加载同一个插件包。最终不再维护 eha-tool 的第二套 HTML、表单和图表。迁移期间旧 UI 只做必要修复，新功能以服务接口和 Fieldkit 为主。

本轮仍只覆盖 EHA，Ranger 不进入迁移。首个完整验收平台定为 macOS Apple 芯片，先使用当前已验证的 DSH Web 宿主；Linux 保留现有开发与 Web 验证路径。官方 Desktop 作为同一插件的额外宿主单独验收，不作为引入自研桌面程序的理由。Windows 不纳入本轮交付承诺，后续需要独立验证凭据 ACL、原生工具、CAN runtime 和驱动。

## DSH 零修改约束

- 不 fork DSH，不修改宿主源码、运行时、官方 bundle 或已安装的官方依赖包，不增加 EHA 专用宿主接口，不制作定制 DSH 发行版。
- 允许使用官方插件扩展点，以及本插件的 `package.json`、`cordis.patch.yml`、配置项、Remote 类型和插件生成产物。`cordis.patch.yml` 是插件声明式配置，不是修改 DSH 源码。
- 工作台中的连接、观察、配置、控制、试验、记录和服务设置均为插件内部视图。宿主缺少 EHA 专用导航或设置入口时，在插件面板内实现，不要求宿主新增功能。
- 当前 `scripts/build-dsh.mjs` 会复制并修补 `0.2.0-rc.2` 的 Typert 生成器；它没有修改已安装 DSH 运行时，但仍属于官方工具代码的构建期补丁。本计划采用更严格目标：P0 消除这项依赖，后续从未经修改的官方包构建插件。
- P0 优先验证调整插件自身类型导出和生成器输入是否足够；若必须选择另一个已修复的官方版本，先完成兼容验证并精确锁定版本。没有可用的官方扩展路径时，该项验收不通过，不用宿主补丁绕过。

产品导航建议固定为“连接与总览、遥测与诊断、配置与维护、控制、试验、记录、设备服务设置”。右侧沿用一个原生对话区；当前目标和执行结果由插件共享服务投影，切换视图不新建设备连接。

## 必须保持的规则

- 普通按钮不经过模型；对话使用同一能力接口。未配置模型、模型超时或额度不足，不影响人工按钮工作流。
- 只读、配置维护、控制三类能力分别声明。当前 `/integration/v1` 保持只读，不直接向其中添加写入动作。
- 每项设备请求绑定服务实例、目标、连接代次及 UID/run_nonce。连接重建、设备替换或实例重启后，旧上下文拒绝执行。
- 界面切换、绘图暂停、窗口关闭、HTTP 超时和解除观察不等于 Stop。停止是显式能力；有界试验已有的自动停止规则继续由 eha-tool 执行。
- 连接和重连不启动心跳、不恢复目标、不重放维护动作。未知结果不自动重试。
- 区分服务受理、本地提交、收到查询回复、观察到状态和设备实际效果。维护操作没有固件操作键或历史结果查询，不能新增虚假的“保存成功”回执。
- 用户输入物理量和配置原文保留十进制文本，Rust 按现有规则一次转换为 f32；计数与时基保持整数或十进制字符串。浏览器显示值不回流为原始配置。
- API token 仅由本机后端读取，不进入浏览器、模型、报告或仓库。默认仅监听回环地址，不把远程设备服务纳入此次迁移。
- 独立进程争用与同一服务内的请求互斥分别处理；本机锁不宣称能约束外部 CAN 发送者。
- 保留现有 CLI 的一次性直连语义；共享持久服务必须显式选择 `--via-service` 模式，不能仅因发现服务而静默改变脚本行为。

## 接口约定

以下 `/service/v2` 路径与新增命令都是拟定接口，并非当前已实现能力。合同在 P0 收敛到 SDK 仓库的 `crates/tool/service-api.md`，消费方只引用它，不维护另一份真相。

### 服务启动与版本

- 新增 `eha-tool serve --port PORT --token-file PATH`，并保留现有 `--runs-dir`、`--odrive-python` 配置能力。成功监听并准备好执行核心后才报告就绪。继续限定回环地址、Bearer 认证、0600 凭据文件和拒绝 Origin；保留现有 `webui` 作为共用执行核心的过渡入口。
- `GET /service/v2/describe` 返回 `api_version`、`tool_version`、`instance_id`、配置格式版本、明确能力列表与限制。插件按能力显示入口，版本不兼容时禁止相关操作。
- 实例发现、凭据和 PID 放每用户私有数据目录，包含进程身份与实例标识，处理陈旧记录及端口占用。不会读取仓库里的固定机器路径。
- Fieldkit 插件提供“启动设备服务”和“连接已有服务”。后端以固定可执行文件和参数数组调用 `eha-tool serve`，不经过 Shell；先检查二进制版本、现有实例和就绪结果。启动只创建服务，不自动连接设备、启动心跳或恢复目标；旧连接档案中的自动连接设置须作为迁移项显式处理，不能继承为默认启动副作用。
- 启动独立服务需要的本机进程能力由插件后端承担。服务不会随面板卸载、插件热重载或 DSH 退出被自动终止；外部已存在的服务不归插件清理。界面提供显式服务退出入口，并显示活动会话与未决影响；退出仍不宣称设备已停止。

### 连接、观察和事件

| 接口 | 语义与主要输入 |
| --- | --- |
| `GET /service/v2/adapters`、`GET /service/v2/profiles` | 复用已有适配器发现及连接档案 |
| `POST /service/v2/profiles`、`DELETE /service/v2/profiles/{id}` | 复用现有保存、UID 绑定和删除规则 |
| `GET /service/v2/targets` | 区分未连接候选、已连接会话及发现受限原因 |
| `POST /service/v2/scans`、`GET /service/v2/scans/{id}` | 对明确 CAN 通路和节点范围发起扫描，沿用现有试验与控制互斥；不能隐式全网扫描 |
| `POST /service/v2/connections` | 明确 USB 候选或受管 CAN 档案；首次仅做既定连接与身份核对 |
| `POST /service/v2/connections/{id}/reconnect`、`POST .../disconnect` | 显式物理会话管理，不等于观察解绑 |
| `POST /service/v2/bindings`、`DELETE .../bindings/{id}` | 为调用方附着或解除观察，不关闭设备连接 |
| `GET /service/v2/bindings/{id}/snapshot` | 读取服务缓存、身份、连接及数据有效性 |
| `POST /service/v2/bindings/{id}/reads` | Status、Measurements、Diagnostics、配置 Factory/Startup/User 的固定查询，不接受任意 SDK 函数名或 shell 命令 |
| `GET /service/v2/config/schema` | 使用 SDK 发布的配置 schema；浏览器不另建校验规则 |
| `GET /service/v2/events?after=CURSOR&limit=LIMIT` | 后端认证的游标事件批次：连接、遥测、操作、试验、记录；提供序号、来源时间与丢失标记，批次上限由 describe 声明 |
| `GET /service/v2/recordings`、`GET .../recordings/{id}` | 按服务返回的记录 ID 列举和导出，不接受任意文件路径 |

首版固定采用带游标的有界批量读取。Fieldkit 后端消费事件，再通过插件的 `getEvents({after, limit})` Remote 投影给客户端；浏览器不直接持有 eha-tool token。可见面板按现有旧 UI 的 250 ms 节奏串行更新，最多一个观察请求在途；隐藏或卸载时停止前端轮询，服务采集和记录独立继续。已验证的 DSH 会话目录订阅不能作为设备事件流的验收证据；官方流式 Remote 留待确有性能需求时再评估，不作为本次迁移依赖。

慢客户端不能阻塞设备循环；事件缓存有界。游标越界时明确返回缺口并重新取得快照，不能把遗漏部分伪装成完整记录。暂停图表只暂停绘制，采集和记录继续。

v2 快照分开提供 `read_permit` 与 `control_effect`：前者表示调度器能否安排查询，后者保留动作效果是否未知。只有 P4 的 SDK/传输调度验收通过，才可在 v1 原本拒绝的部分状态下安排 v2 查询；查询成功不清除未知效果，也不因此扩大控制请求准入。否则继续显示缓存并明确拒绝主动读取。

### 写入和控制

| 接口 | 允许的操作 |
| --- | --- |
| `POST /service/v2/config/validate` | 完整原始配置文本的离线校验，不要求设备连接 |
| `POST /service/v2/control-reservations`、`DELETE .../control-reservations/{id}` | 明确声明单台或群组的控制占用；观察绑定可以有多个，写入者只能有一个；释放不等于 Stop |
| `POST /service/v2/bindings/{id}/maintenance` | `save_and_restart`、`restore_factory_and_restart`、`reset_application`、`enter_update` |
| `POST /service/v2/bindings/{id}/heartbeat` | 显式 start、stop、once；停止心跳与停止控制分别展示 |
| `POST /service/v2/bindings/{id}/target` | position、velocity、force、impedance，保留原始十进制输入 |
| `POST /service/v2/bindings/{id}/stop` | 显式普通停止，独立高优先级受理路径 |
| `POST /service/v2/bindings/{id}/trials`、`POST .../trials/{trial_id}/stop`、`POST .../trials/{trial_id}/target` | 复用已有有界试验与位置更新语义 |
| `POST /service/v2/groups`、`DELETE /service/v2/groups/{id}` | 创建或释放由明确绑定组成的群组引用；成员身份固定，释放不停止、不断连 |
| `POST /service/v2/groups/{id}/trials`、`POST .../stop`、`POST .../heartbeat` | 显式成员集合，返回逐设备结果；不承诺群组原子性 |
| `POST /service/v2/bindings/{id}/recording` | 显式开始/结束服务侧记录，不随绘图状态变化 |
| `GET /service/v2/odrive/devices`、`POST /service/v2/odrive/read` | 保持现有独立 ODrive USB 只读边界 |

写入请求共同携带 `instance_id`、绑定身份与连接代次、`request_id`、固定动作及动作参数。`request_id` 只用于本机受理去重和追踪，不发送成固件操作键。同实例同编号同参数返回已有记录；同编号不同参数拒绝；实例变化后旧请求拒绝，不跨重启自动重发。

请求同一性包含原始数值文本，不能由显示值重建。操作记录容量与保留期在 describe 中声明；未决记录不得淘汰，记录超期或容量不足时明确拒绝普通提交，不能因遗忘去重信息再次执行旧请求。人工 Stop 的受理不得被普通请求队列或账本容量挤占。通过模拟缓存回收和进程崩溃验收这一边界。

`GET /service/v2/operations/{id}` 查询的只是本机执行记录。记录分开呈现 `admission`、`submission`、`observation`、原始错误与时间，不把“HTTP 200/202”映射成设备成功。取消只适用于尚未提交的请求或后续读取；已经提交的设备动作没有通用撤销含义。

权限在后端检查。默认只读；用户明确启用指定目标的维护或控制能力后，表单和对话才获得对应固定动作。对话不能以自由文本、任意路径或不同会话绑定绕过同一门禁。现有模型工具按阶段扩展，不一次开放全部控制。

模型工具的对话归属由 Fieldkit 的可信 `exec.agent.id` 确定，不能从模型参数中接受替代身份；浏览器 Remote 的会话编号只用于同一操作者的路由。服务 token、binding 和 control-reservation 不构成多用户认证系统，本计划不宣称隔离持有同一 OS 用户凭据的进程。

维护、目标和试验请求还须匹配当前控制占用。群组在本机一次核对并占用所有成员，不能抢走其它工作流正在控制的设备；这不意味着设备侧原子执行。窗口关闭和超时不自动移交未决控制权，恢复或接管必须显式处理。具有目标操作权限的人工 Stop 不被另一对话持有的占用阻挡；仍要核对身份、代次及现有试验停止入口。

## P0 插件边界与服务合同冻结

**范围：** dsh-fieldkit 的公开扩展点、构建链、宿主兼容矩阵和 Remote 能力；SDK 的完整旧 UI 能力对照与服务合同。保留当前基线，不重做已经通过且未变化的只读测试。DSH 本身不属于改动仓库。

- [ ] 在独立官方 DSH profile 中验证插件自有导航、表单、图表容器、原生对话、服务设置、后端固定进程调用和 Remote；仅修改插件源文件或用户侧 profile 配置。
- [ ] 消除 Typert 构建期补丁。在干净环境中从精确锁定的官方依赖完成构建和打包，安装插件后验证实际 Remote 往返；不只验证 TypeScript 编译成功。
- [ ] 核实批量事件读取/订阅、原文文件导入导出及记录下载的公开路径。优先普通文件选择与下载、插件 Remote 和记录 ID；不要求宿主新增 IPC、协议处理器或文件系统权限。
- [ ] 以现有 `webui.rs` 路由、`session.rs::Command`、试验和记录代码建立“现有功能—新接口—新面板—验收用例”清单；每项都有去向。
- [ ] 冻结上述接口、版本拒绝、请求去重边界、实例变化及来源时间语义；明确当前 v1 的兼容期。
- [ ] 确定服务内调度以及 CLI 的连接持有策略；记录当前永久 `unresolved_target` 限制与后续查询调度之间的关系。

**验收：** 未修改的官方 DSH 能安装实际插件包，显示一个工作台和一个原生输入框；无模型凭据可使用按钮。构建和运行均无官方包补丁、私有 API、私有运行时注入或 monkey patch；错误版本明确拒绝。每项旧能力都有明确映射；文件传递、事件和服务进程管理在插件边界内完成。新宿主版本引入时再执行对应兼容检查，不能把当前 Web 的验证直接算作 Desktop 通过。

## P1 独立设备服务与 CLI 协作

**SDK 改动：** `crates/tool/src/main.rs` 增加 serve 入口；从 `webui.rs` 抽出服务生命周期、HTTP 与设备执行核心；`webui/workbench.rs` 和 `webui/integration.rs` 迁入服务目录。`session.rs`、`connections.rs`、`trial.rs`、`recording.rs`、`runtime.rs` 继续复用。旧页面只作为服务的兼容适配器。

**Fieldkit 改动：** `src/integration.js` 增加 v2 协商；`src/service.js` 管理同一服务连接；`src/index.js` 增加本机服务配置；新增插件内部 `src/owner-process.js` 与 `src/client/ServiceSettings.ts` 承担启动/附着及状态呈现。凭据、就绪和错误由后端处理，DSH 无需改动进程管理代码。

- [ ] 不加载静态页面即可提供 describe、目标、绑定、缓存及既有五项只读查询；v1 行为保留。
- [ ] 将 HTTP 收发、浏览器背压与设备执行解耦；保持一个物理通路的唯一 SDK 客户端，不能用两个客户端分别“读”和“停”。
- [ ] 保留原 CLI 的直连行为，并在打开设备前获取排他锁；已有服务占用同一通路时返回 `owner_busy`。新增显式 `--via-service` 模式，把同样的固定命令交给服务已有会话；服务失败或版本不兼容时不回落直连。
- [ ] 锁覆盖 USB 稳定序列号或受管 CAN 适配器的稳定身份及物理通路，不能通过更换 CAN 节点、模式或 Python 解释器绕过同一通路的占用。高级 CAN 采用规范化接口/通道或明确资源标识；不能识别为同一物理通路的外部别名属于明确限制。已有连接档案文件锁不能替代设备锁，多个节点复用同一网络所有权。
- [ ] 原 `webui` 使用同一执行核心和锁；不会因为兼容旧入口而增加第二套连接持有者。

**验收：** 无页面服务通过现有只读合同；双服务、CLI 与服务、旧 UI 与服务争用时只允许一个持有者；刷新、退出 DSH 不重连、不停止、不重复提交。服务重启使旧绑定失效，版本不匹配无回落。此阶段不因新增 serve 就开放控制接口。

## P2 连接 观察 曲线与记录迁移

**SDK 范围：** 发布连接档案、USB/CAN 显式连接/断连/重连、发现与扫描、遥测事件、记录读取及 ODrive 只读接口；复用现有受管 CAN runtime 和 UID 门禁。主动扫描按现有试验/控制限制执行。

**Fieldkit 范围：** 保留 `src/client.ts` 为面板入口，逐步拆出 `src/client/Connections.ts`、`Observation.ts`、`Recordings.ts`；Remote 与共享服务增加对应方法。设备列表、连接状态、数据来源、诊断和曲线分别呈现。

- [ ] 迁移连接档案编辑、适配器选择、显式重连和断连；观察解绑单独保留。
- [ ] 增加实时曲线、来源时间、过期/缺口标记、记录开始/结束、历史记录与导出；重用记录格式及第三方图表库，保留许可。
- [ ] 保留当前首错即停的诊断和原始证据；诊断进度通过同一服务暴露，按钮与对话看到同一结果。
- [ ] 迁移 ODrive USB 只读面板，不把它当作 H723 CAN 通路状态。

**验收：** USB 与受支持 CAN 接入均可显式选择正确设备；同序列号歧义、UID 不符和拔插明确拒绝；事件丢失有标记；图表暂停不停止采集；慢页面不影响服务；记录断开后保留部分数据；关闭对话不删除设备连接。ODrive 枚举、读取、解释器缺失和超时分别验收，不扩大其只读能力。

P2 的 v2 主动读取仍遵守 v1 的心跳、试验、非 Idle 与 `unresolved_target` 门禁；P4 调度验收前只能显示对应缓存或明确拒绝查询，不能为补齐页面而提前放宽。

## P3 配置和维护迁移

**SDK 范围：** 发布配置 schema、原文检查、配置读取，以及与现有 Command 对齐的四项维护接口。本计划不增加分离的 apply/save 事务，也不把 enter-update 描述成完整固件刷写流程。

**Fieldkit 范围：** 新增 `src/client/Configuration.ts` 和 `Maintenance.ts`；表单展示单位、范围、当前 Startup/User 差异和提交的完整配置。未编辑的原字段保留原文；编辑值按十进制文本交给 SDK。

- [ ] 迁移导入、编辑、静态检查和原文导出；校验仍调用 SDK。
- [ ] 用户明确提交目标及完整配置后执行 save-and-restart；返回本地提交结果和需重连核对的状态。
- [ ] 用户显式重连同一 UID 后读取 UserRecord、Startup 和启动来源，展示当前实际采用状态；不把新 run_nonce 单独作为保存成功证据。
- [ ] 迁移恢复出厂并重启、复位应用和进入更新；对话和按钮共享身份、授权及未知结果规则。

**验收：** 非法值、重复字段、非零下溢和大整数不会因浏览器转换而漏检；重复请求不会再次写入；响应丢失、进程重启和断连均不会自动重放；错误 UID 不提交；有可复核的提交记录和后续读取证据。用明确设备范围进行维护验证后，才宣称设备工作流可用。

## P4 控制调度 持续目标与试验迁移

**SDK 范围：** 优先解决同步 SDK 查询等待对服务循环的阻塞，再发布心跳、目标、Stop、单台/群组试验。当前已启用的心跳由 I/O worker 维持，但服务受理新的心跳操作、Stop 和试验调度仍受同步循环影响；Stop 与普通短查询共用发送 lane，当前没有 Stop 优先级。迁移保留 SDK 与 trial 的控制语义，界面不承担实时调度。

**Fieldkit 范围：** 新增 `src/client/Control.ts`、`Trials.ts`；显式选择控制对象，显示输入单位、限值、目标、观测值及数据年龄；停止入口在模型不可用时仍可操作，也不被普通查询或模型请求的 busy 状态禁用。

- [ ] 把 Stop 受理、心跳调度、试验截止与普通读取分开调度。仅将阻塞调用搬到后台线程但仍占用同一 SDK 客户端，不算完成。
- [ ] 在 SDK 的 `src/host/mod.rs` 请求匹配和回复消费边界提供保持唯一 Client 的可轮询查询操作，例如 begin/poll/cancel；取消只结束等待，不撤回已提交字节。调度器可以在本地操作边界处理 Stop，不允许多个线程竞争消费同一 Client 的回复。
- [ ] 用延迟和永不返回的查询注入，验证 Stop 不等待整个 5 秒查询超时才被处理；在可控测试时钟下，于当前有界处理步结束后的下一个调度步开始尝试本地提交。记录该延迟与传输拒绝结果，心跳和试验截止继续处理；不承诺抢占已进入驱动的发送或机械停机时间。
- [ ] 保留现有大/慢请求体隔离：慢上传、满观察队列和大记录下载不能占住 Stop 的 HTTP 受理与 owner 调度。验收同时记录请求受理、本地提交尝试和后续设备观测，不能只测按钮可点击。
- [ ] 迁移 position、velocity、force、impedance、显式心跳和普通 Stop；持久目标不随“到达目标”或 UI 超时结束。
- [ ] 迁移既有单台/群组有界试验、位置更新和记录联动；群组逐台报告准备、提交、停止与未知状态，部分失败不伪装成原子成功。
- [ ] 保留 v1 的 `unresolved_target` 语义。v2 的查询准入与动作效果证据单独定义，不能为恢复按钮而用本地 Stop 或迟到 Idle 清除未知结果。验证心跳、查询大记录、Stop、乱序回复和身份变化的组合；不能证明调度边界时保持拒绝，不以第二个 SDK 连接绕过。

**验收：** 延迟查询、满队列、慢客户端、请求重复、错误代次、两个对话或 CLI 同时控制、群组成员已被占用、UI 关闭、DSH 重启、通路断开、试验到期和停止结果未知均有确定行为。通过 USB 与受支持 CAN 的明确实板场景后才能开放控制交付。没有结果证据时界面显示未知；服务或 UI 恢复后不恢复目标。

## P5 插件交付和完整替代验收

**范围：** 未修改的官方 DSH、Fieldkit 插件、匹配版本的 eha-tool 及其现有私有 runtime。平台打包继续使用 SDK 的 `scripts/package_tool.py`，不把 Linux 容器二进制当作 macOS 产物。插件归插件仓库发布，设备二进制归 SDK 发布；独立版本通过 describe 协商，不复制设备实现进插件包。

- [ ] 提供面向操作员的安装及首启流程，校验 DSH/插件/服务版本，配置私有数据目录，明确启动或附着设备服务。
- [ ] 从干净官方 DSH 和已安装的匹配 eha-tool 开始，安装插件后即可在插件内配置、启动或附着服务。服务和设备运行期间不需要用户另外打开旧 WebUI；安装前置依赖与日常操作分别记录。
- [ ] 验证日常操作不使用终端、不配置模型也能完成全部按钮工作流；对话在有模型配置时解释同一份证据。检查插件的模型工具、授权与按钮保持同一目标和同一结果来源。
- [ ] 如交付官方 Desktop，单独核对该发行包的精确版本、公开插件安装方法及数据目录，再用同一插件完成验收；普通 npm DSH 不直接改写 Desktop 的内部目录。
- [ ] 覆盖窗口关闭、应用退出、服务异常退出、升级、模型断网、记录导出及权限错误；恢复流程不自动重放设备动作。
- [ ] 在退役候选版本中将 DSH 设为默认入口，按全部功能对照表跑一次完整操作员验收；旧 UI 只用于明确的问题定位，不能成为缺失功能的永久入口。

**验收：** 首个支持平台在未修改的官方宿主中全流程可用；没有操作必须返回旧 UI；CLI 与服务并存不争用；插件卸载后宿主可正常使用；重新安装可恢复用户数据与服务附着。安装、升级与数据保留可复现，宿主升级重新通过插件兼容验收，不静默跳过版本限制。

## P6 旧 WebUI 删除门槛与清理

最早删除时点为 P5 的退役候选周期完成之后的下一次明确破坏性发布。具体日期由通过验收的进度决定；不是 P1 的服务抽离完成，也不是 P2 的只读页面完成。

以下条件全部成立才可删除：

1. 旧页面每项能力已迁移，或已由用户明确决定从产品中取消；没有静默遗漏的功能。
2. 新界面、CLI 和服务共享单一执行实现；身份、代次、数值与结果语义保持一致。
3. P4 调度门槛及 USB/CAN 实板工作流通过，已知限制有明确产品处置；旧 UI 不再承担控制补救入口。
4. 独立服务和 CLI 可在没有 DSH 时运行；DSH/模型故障不破坏服务的既定生命周期。
5. 首个交付平台的安装、启动、记录导出、升级和迁移说明通过验收；需要支持的其它平台按同样条件完成。
6. 用户资料和历史记录保持可读取；回退到旧发行包不会自动连接设备或重放操作。
7. 全部产品界面和能力入口来自 Fieldkit 插件；干净官方 DSH 可完成安装、运行、升级和卸载，不存在为 EHA 保留的宿主分支、官方包补丁或未公开扩展点。

**删除范围：** `crates/tool/webui/static/`、其静态 ASSETS/页面路由、已无消费者的旧 `/api/*` 适配器、`crates/tool/webui/tests/` 中仅服务旧前端的测试、其 package/lock 文件及未再使用的图表 vendor 资源。SDK 的 `scripts/check.py` 移除旧前端测试入口，保留服务和 SDK 检查；Fieldkit 验收仍归插件仓库。逐项核对许可与依赖，仍被 DSH 使用的第三方库保留相应许可。

**保留范围：** 已迁入 service 的 Workbench/HTTP/认证逻辑、ToolSession、连接档案、CAN runtime、trial、recording、CLI 与 SDK。当前 `webui.rs` 同时包含页面与服务，不能整文件提前删除。

**旧命令：** 删除阶段撤销 `eha-tool webui` 的页面功能，提供一个明确兼容周期的迁移提示；是否保留 serve 别名必须在发布说明写清。没有消费者的旧 `/api/*` 可删除；`/integration/v1` 的协议兼容期单独处理，不因删除 HTML 顺带破坏已发布客户端。

**验收：** 从发行目录移除全部旧页面后，DSH 与 CLI 的合同、打包和端到端验收仍通过；包内没有遗留页面入口。同步工具与 SDK 的 README、CONTRIBUTING、CAN 接入指南、AGENTS，以及实际调用脚本，确保不再引用已删除命令或路由。

## 插件安装与宿主兼容边界

当前已经验证的是 `0.2.0-rc.2` 的 DSH Web 与 Fieldkit 安装包。P0 在这一基线上验证不依赖构建补丁的路径；若更换官方宿主版本，兼容表、依赖锁与真实安装验收同时更新。无需为了 EHA 功能修改宿主的侧栏、设置页、会话管理或进程管理。

交付组合为“官方 DSH + Fieldkit 插件 + 独立 eha-tool 服务”。官方 Desktop 是否纳入该次发布，以同一插件在该宿主上的验收结果为准；它不产生另一套 EHA 页面。公开下载地址上的默认版本也不等于已验证版本，安装指引须给出实际兼容范围。

本计划不包含 EHA 定制 DSH、独立 Electron/Tauri 外壳、宿主源码补丁或私有接口适配。不能完成某项公开插件扩展时，先收敛插件实现或官方版本选择；不以增加宿主维护责任作为迁移完成条件。
