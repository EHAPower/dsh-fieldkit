# Fieldkit 安装与首启

本指南对应未修改的官方 DSH Web、Fieldkit `.tgz` 和匹配的原生 eha-tool。P1 与部分 P2 只读原生旅程已取证，P3 候选仅在合成环境安装和操作。跨 XDG 双服务互斥的真实失败已修复，原生 CAN 子例复验通过；完整操作员旅程、升级保留、卸载重装及官方 Desktop 仍待验收。本指南不是完整替代旧 WebUI 的发布声明。证据见[迁移进度](eha-migration-progress.md)和[用户旅程](eha-user-journey.md)。

| Fieldkit | `0.2.0`：P1 源码 `89e5acd`；主界面 P2 阶段 `f14765a` 已安装；P3 后续候选仅装合成 profile | 最终候选的源码及安装包版本；同名版本不能替代候选识别 |

当前主界面稳定组合仍为原生 SDK `9fb7f27` / P2 插件 `f14765a`。R2 原候选 NOT PASS 的记录保留；SDK 六项及插件后续源码发现已独立关闭，新完整插件包（582246 B / 58 files）已安装合成 profile，实际 P4 界面验证中。SDK 已提交 `fd636b6` 并设置代码控制门 `RELEASED=true`，这是软件门状态，不是正式发行或实机通过。P3/P4 实机写入和运动从未执行，P3/P4 插件只在合成 profile 取证，实际新 UI 缺陷仍在修复。

先按官方 DSH 对应版本的安装说明安装匹配的宿主，并让其插件管理所需的 Node 与 pnpm 在启动环境中可用。实际安装曾因缺少 `pnpm` 失败；修正启动环境的 PATH 后，公开插件安装命令成功。不要通过修改官方包解决环境问题。

eha-tool 路径必须指向与 DSH 运行主机系统和架构兼容的完整原生发行目录内的可执行文件，保留配套 `runtime` 和许可。devbox 中的 Linux 构建用于开发验证，不能用于 macOS 主机。发行作者按[SDK 构建与打包说明](https://github.com/EHAPower/eha-sdk#readme)使用 SDK 的 `scripts/package_tool.py`；操作员使用完整发行包，不需要为标准 CAN runtime 自行安装 pip 或创建 venv。ODrive 的解释器另行配置，不由 CAN runtime 的可用性证明其可用。

## 安装到独立 profile

以下路径是占位符，替换为本机取得的候选包；使用独立 profile 保留原有宿主配置。

```sh
dsh --version
dsh --profile fieldkit --from-default-profile web --help
dsh plugin --profile fieldkit add /absolute/path/to/ehapower-dsh-fieldkit-0.2.0.tgz
dsh --profile fieldkit --no-open
```

自定义 profile 本身就是 Web 入口，启动命令不追加 `web`。首次从官方 Web 模板建立 profile 与保留已安装插件是两件事：不要再次用模板初始化代替升级或无模型验收。

DSH 的 profile 配置与插件依赖归宿主管理；默认 DSH home 为 `~/.dsh`，可由 `DSH_HOME` 选择。Fieldkit 服务设置和服务数据归运行主机当前用户的数据目录，独立于 profile。隔离验收时还须给 Fieldkit 设置独立的 `XDG_DATA_HOME`；只更换 `DSH_HOME` 仍会共享当前用户的服务设置。更换 profile 或 DSH home 不会自动迁移 Fieldkit 数据，也不能单凭换目录证明没有模型凭据；DSH 还可能从环境和 `.env` 读取凭据。不要复制或公开实际凭据文件。

## 配置并启动服务

打开 EHA 工作台的“服务设置”，填写并保存固定字段：

| 字段 | 操作员填写内容 |
| --- | --- |
| eha-tool 绝对路径 | 匹配版本的原生发行包可执行文件 |
| 私有数据目录 `dataDir` | 当前用户拥有的私有绝对目录；目录权限 `0700`，现有祖先目录须满足安全检查 |
| 服务端口 | 未被其他进程占用的本机端口，默认 `18080` |
| 记录目录（可选） | 需要单独保存 SDK 运行记录时填写；留空使用 SDK 默认目录 |
| ODrive Python 绝对路径（可选） | 带 `odrive==0.5.1.post0` 及其 USB 依赖的原生解释器；留空由官方工具选择 |

设置只接受上述路径与端口，不接受任意命令或附加参数。保存 ODrive 路径只证明配置已保存；P2 原生插件已另行通过枚举、明确选择和独立只读，不代表完整 ODrive 异常恢复旅程通过。

先点击“发现 / 附着服务”。它核对认证后的服务实例；文件或 PID 存在不代表就绪。没有服务且设置正确时，再点击“启动服务”。启动仅创建独立服务，不自动连接设备、启用心跳或恢复目标，包括旧连接档案标记了自动连接的情况。保存设置或更换实例会使旧绑定失效，应明确重新选择目标。

服务发现文件和 token 文件应为当前用户的 `0600` 私有文件。token 只由主机进程读取，不能粘贴到浏览器、对话或报告中。服务精确协议和 capability 以配套 SDK 中的 `crates/tool/service-api.md`为准。默认 `service-v2`；版本、认证或连接失败会拒绝操作，不自动回落。`integration` 是显式 v1 兼容入口，`legacy-cli` 是显式旧直连，两者不是 v2 故障恢复办法。

## 已取证的只读按钮流程

模型配置提示可以选择 **Configure later**。实际无凭据隔离环境已完成离线配置检查、服务启动、USB 显式连接、缓存查看和六步只读诊断；启动后没有设备连接或心跳。模型默认名称出现在宿主界面不表示已有凭据。

1. 在工作台配置并启动或附着服务。
2. 刷新候选，显式选择并连接 USB 目标；核对身份和连接代次。
3. 查看缓存及其年龄，再在读取门允许时开始只读诊断。首次失败或身份变化停止后续读取并保留部分证据。
4. 离线配置检查输入完整 JSON 原文，交由 SDK 检查；不经显示精度或 JavaScript 数值转换重建配置。

这些按钮不需要模型调用。P2 原生 USB 档案连接、单节点 CAN 扫描/连接、USB/CAN 六步诊断 JSON 下载及独立 ODrive 只读已取证；USB/CAN 是同一物理设备，不算多节点或群组验收。无模型隔离 profile 也已附着主服务既有 USB 连接完成六步诊断，没有新开 Client。

聊天需要另行配置模型。模型 USB 诊断曾前五项成功、User 查询超时，面板实时显示不完整及首错，旧实时同步缺陷已闭。后续独立诊断的一次完整 16384 B User 读取及 60 秒被动遥测未复现错误，原超时原因仍未关闭，不能据单次成功反复重试。

人工“仅缓存”要求曾被已安装模型流程误作主动诊断。新包使用无参数 `fieldkit_snapshot` 读取当前会话已选绑定的缓存，缺能力或缓存失败时停止，不用主动诊断补齐。该工具、SOP 分流及输出预算软件审查已通过，尚待新包实际模型 UI 复测。

P3 合成候选已操作原文导入/校验/字节相等导出、三配置视图与本地提交/未确认回执查询；保持单表单，未知 reset 回执刷新后仍为同一 operation 的未知/未确认，执行禁用且不自动重试。最新身份错误立即撤销观察和授权、提示重新选择；撤权只禁用维护，保留有效只读观察并提示人工重授。以上均为实际官方界面配合合成服务，没有实际设备保存、复位或配置采用证明。完整 P2 至 P4 旅程仍待验收。

## 生命周期、升级与卸载

关闭页面、退出 DSH 或卸载插件不发送设备 Stop，也不 kill eha-tool。P1 实测 DSH 退出后服务、实例和只读设备连接保持，另一 DSH 可继续附着；页面刷新也保留同一绑定。新服务实例启动后没有旧连接或心跳，不重放操作。活动控制和记录的对应旅程仍待 P4 验收。

如确实需要退出服务，在工作台先核对实例、会话、心跳、试验和未决效果摘要，再明确确认“退出服务”。响应仅表示受理，不能据此判断服务已退出或设备已停止；超时和断连可能是结果未知，不自动重试。P1 只读退出与再启动已验证，P3 修复包在官方 DSH 也已复验退出后服务设置与启动入口仍可用。

升级时保留原生 SDK 完整旧发行目录、DSH profile 配置与插件依赖、Fieldkit 私有设置和服务目录、连接档案、配置原文、报告及 SDK runs。通过官方 Plugins 界面安装指定的新候选包，再核对工具版本、服务描述和能力；宿主升级也须重新验收。更新插件或改工具路径不会替换正在运行的服务实例，需要分别处理服务生命周期并重新附着。回退不自动连接设备或恢复心跳、目标与动作。

旧 SDK 的物理 owner 锁目录随 `XDG_DATA_HOME` 改变，跨隔离环境第二服务曾绕过互斥并导致 CAN 超时/被动断连。`9fb7f27` 稳定 OS 账户 namespace 修复已通过原生跨 XDG CAN 复验：第二服务明确 owner_busy，原服务保持连接可读；切换 profile 或 XDG 不是并行打开同一设备的办法。统一升级前须明确退出所有旧通路 owners，旧自定义 XDG 版本与新版混跑不保证互斥。需要共享读取时显式附着同一个既有服务。

卸载使用官方 Plugins 界面，不顺带删除用户数据、SDK 发行目录或服务凭据，也不清理独立服务。重装后以相同运行用户和数据设置发现服务，重新核对实例与目标。上述数据保留是实施边界；完整升级、卸载重装及各类权限错误仍待 P5 实际验收，不承诺任意版本组合可直接升级。

## 出错后的下一步

| 现象 | 下一步 |
| --- | --- |
| 插件安装找不到 pnpm | 修正官方 DSH 启动环境的 PATH，再执行公开安装命令 |
| 工具版本或能力不符 | 换用对应的原生 SDK 候选；不要改成旧直连规避拒绝 |
| 端口占用或已有实例不能认证 | 核对当前进程、端口、数据目录和权限；不覆盖运行中服务的凭据 |
| 启动超时、结果未知 | 发现 / 附着并人工核对实例；不反复启动 |
| 绑定过期或身份改变 | 保留已有证据，刷新并明确重新选择；不重放旧请求 |
| CAN 被动断连但概要仍显示连接 | 保留异常证据，核对实际通路；概要根因修复尚待原生复验，不据旧概要继续操作 |
| USB User 查询超时或传输错误 | 保留部分报告与首错，停止后续读取；当前原因仍调查，不自动重试/重连 |
| ODrive 缺 Python 包或 USB 依赖 | 指向 SDK 要求的专用解释器，单独核对其只读能力 |
| 模型没有配置或暂不可用 | 使用已取证的只读按钮子流程；完整模型故障恢复旅程仍待验收 |

采集完整只证明本次读取步骤与身份连续，不证明配置已采用、设备安全、机构停止或整个迁移完成。

当前阶段的补充状态：SDK `fd636b6` 已取得目标 macOS arm64 原生构建；完整 P3/P4 插件包已安装隔离合成 profile，开始实际按钮旅程。主设备 profile 仍使用上述只读稳定组合，实际 UI 新发现的缺陷正在修复；这里不宣称完整新候选交付通过。
