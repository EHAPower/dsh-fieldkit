# EHA 插件用户旅程验收

本表用于迁移验收准备，不证明功能已实现或测试已通过。当前所有实际结果均为 **待验收**。范围与阶段以[迁移计划](superpowers/plans/2026-10-13-eha-dsh-ui-migration.md)为准；服务正式接口只引用配套 SDK 的 [`crates/tool/service-api.md`](../../eha-firmware/eha-sdk/crates/tool/service-api.md)，其编写、冻结及实现尚须对应阶段验收，本表不复制协议或定义新接口。

## 执行与证据约定

- **UI**：使用实际打包并安装的插件、未修改的官方 DSH 和真实 eha-tool 服务，通过浏览器或桌面实际操作。后端测试不能替代这一证据。
- **实物 UI**：只能在身份已核验的 **nzh-mbpm1**，使用兼容该平台的原生程序及既有 SOP 执行。USB、每种承诺支持的 CAN 接入、ODrive、单机及群组分别留证；缺设备、适配器或恢复条件时仍为待验收并注明阻塞，不能以合成 PASS 补齐。
- **合成 UI**：真实界面与服务配合合成传输或受控故障。记录注入点、错误原文及副作用次数；不得为了验收在实物运动中拔线、替换身份或制造未知危险。正常实物流程仍须另验。
- 实物写入或有界运动前记录目标、身份、原始配置、范围、速度/力限制、停止条件和恢复路径；首个必要门禁失败即停该设备动作链，未知副作用不自动重放。
- 每项证据记录宿主/插件/服务精确版本、平台、用例、时间、结果及必要截图/日志入口。动作证据分别记录服务受理、本地提交、回复、新鲜观测、设备执行与可核验的机械效果；只取得其中一层时如实保留，不推断其余层。
- 原始日志、设备身份、配置与凭据保存到私有位置；本表只填脱敏的证据索引。表中“待采集”是证据要求，不是已有产物。
- 后续填写实际结果时区分通过、失败、阻塞和未执行，并保留合成/实物类型；不重复验证未变化且已取得充分证据的输入。

| J08 无模型全按钮旅程（实物 UI） | 无模型配置执行连接、观察、配置、维护、控制、试验与记录的已授权流程 | 人工按钮均独立可用；模型状态不成为设备能力门禁 | 隔离无凭据环境的离线按钮通过；完整设备旅程待验收 | 新 DSH_HOME、空 cwd、清空继承环境；官方 API key 提示选稍后配置后完成 J28 的缺字段子例 |

| J10 模型断网/失败（合成 UI） | 让模型断网、超时或额度失败；继续按钮操作并使用 Stop | 对话明确报错；人工流程继续，Stop 可发现且不被模型 busy 禁用 | 待验收 | 待采集：模型错误、按钮/Stop 操作与受理日志 |
| J11 显式退出服务（UI；实物仅按 SOP） | 查看活动会话及未决影响后执行服务退出，再启动/附着 | 明确服务生命周期与设备影响；退出不标为设备已停止；重启不重放动作 | 待验收 | 待采集：退出提示、服务日志、恢复后目标状态 |
| J12 升级与额外宿主（UI） | 升级匹配工具/插件/宿主并重开；若承诺 Desktop，使用该官方发行独立验收 | 数据保留、版本重新协商；不把 Web 结果当作 Desktop 通过 | 待验收 | 待采集：升级前后版本/数据、宿主各自安装与旅程证据 |
